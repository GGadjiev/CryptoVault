## 📌 О проекте

**CryptoPulse** — трекер крипторынка: топ-50 монет, детальные страницы с графиком, избранное и личный портфель сделок с расчётом `P&L`.

- **Стек:** React 18 + TypeScript (`strict`) + Vite, React Router v6, Zustand, Axios.
- **API:** CoinGecko (бесплатный, без ключа; лимит ~10–30 req/min).

---

## 📐 Слои и правило зависимостей

```text
app/       → входная дверь: сборка приложения
  ↓
pages/     → коридоры: экраны-компоновщики
  ↓
features/  → комнаты: домены, вся бизнес-логика
  ↓
shared/    → фундамент: ничего не знает о доменах
```

**Золотое правило:** Импортировать можно *только* слой ниже своего.

| Слой | ✅ Разрешено импортировать | ❌ Запрещено |
| :--- | :--- | :--- |
| **app** | `pages/` | `features/`, `shared/` напрямую |
| **pages** | `features/*` (только через их `index.ts`), `shared/` | `api/*` модулей, `axios`, внутренности модулей |
| **features/\*** | `shared/`; другие модули — только через `index.ts` и только в разрешённом направлении | глубины чужих модулей, `pages/`, `app/` |
| **shared** | только внешние npm-пакеты | `features/`, `pages/`, `app/` |

> ⚠️ **Единственное исключение `features → features`:** `portfolio → market` (портфелю нужны рыночные цены). `market` не знает ни о ком. Если `market` потребовалось что-то из `portfolio` — это не импорт, а композиция через пропсы (слот `renderExtra` в `CoinTable`, см. пункт 5.4 плана).

### Примеры импортов

**✅ Допустимо:**
```typescript
// pages/DashboardPage.tsx
import { useCoins, CoinTable } from '@/features/market';
import { Spinner } from '@/shared/components/Spinner';

// features/portfolio/hooks/usePortfolioSummary.ts
import { useCoins } from '@/features/market';            // разрешённое направление
import { formatMoney } from '@/shared/lib/formatters';
```

**❌ Запрещено:**
```typescript
// pages/DashboardPage.tsx
import axios from 'axios';                                  // страницы не знают axios
import { fetchMarkets } from '@/features/market/api/coins'; // только через витрину

// features/market/components/CoinRow.tsx
import { usePortfolioStore } from '@/features/portfolio';   // обратное направление = цикл

// shared/components/Spinner.tsx
import type { Coin } from '@/features/market';              // shared не знает доменов
```

## 🏛️ Описание слоёв

### `app/` — входная дверь
Инициализация и сборка. `App.tsx` — Layout и глобальные обёртки; `router.tsx` — карта роутов. Бизнес-логики здесь нет и не будет.  
*Рост:* ErrorBoundary, провайдер темы, React.lazy-роуты.

### `pages/` — коридоры
Один файл на роут. Страница — дирижёр: берёт хуки у модулей, компонует компоненты, выбирает отображаемое состояние (`loading` / `error` / `empty` / данные).  
*Проверка тонкости:* страница читается как список блоков — без формул, запросов и парсинга. Страница может компоновать несколько модулей, поэтому стоит выше их.
> `main.tsx` — не здесь: это bootstrap Vite, живёт в `src/`.

### `features/` — комнаты (домены)
Самодостаточные пользовательские возможности. Границы проводятся по словам продукта: «рынок», «избранное», «портфель». Сторы и API-клиенты принадлежат домену и живут внутри него — никаких `src/store` и `src/api` в корне.

### `shared/` — фундамент
Код, не знающий доменов.  
*Тест:* файл упоминает «монету/цену/портфель»? Тогда ему не сюда.  
*Правило второго использования:* выносим в `shared` при втором случае применения, не заранее.

## 🧬 Анатомия feature-модуля

| Подпапка | Что внутри | Правило |
| :--- | :--- | :--- |
| `api/` | axios-инстанс, fetch-функции, сырые типы | единственное место со словами «axios» и `snake_case` |
| `hooks/` | хуки запросов/вычислений | публичный «интерфейс данных» модуля |
| `store/` | zustand-стор + persist | только исходные данные, без вычисляемых полей |
| `components/` | доменный UI | знают DTO, не знают про API |
| `types.ts` | публичный DTO | «язык модуля» наружу |
| `index.ts` | витрина | единственная дверь внутрь |

> **Важно:** Анатомия не шаблонная. У `watchlist` нет `api/` (данные монет берёт у `market`), у `portfolio` тоже нет (своей сети нет). Папка создаётся под реальный код, пустых папок «на будущее» не держим.

### Публичный API модуля (`index.ts`)
- **✅ Экспортируем:** хуки, компоненты-витрины (`CoinTable` — да, `CoinRow` — нет), публичные типы: `export type { Coin } from './types'`.
- **❌ Не экспортируем:** axios-инстанс, fetch-функции, сырые типы CoinGecko, внутренние компоненты. Никогда `export *`.
- **Смысл:** витрина — договор. Внутренний рефакторинг (кэш в `useCoins`, разбивка файлов `api`) не должен касаться потребителей модуля.

## 🛡️ Правила TypeScript

1. Сырые типы CoinGecko (`market/api/types.ts`) **не покидают** модуль `market`.
2. `snake_case` (`current_price`) живёт *только* в `market/api/`. Весь остальной проект — `camelCase`.
3. Типы импортируются снаружи *только* через `index.ts` (`export type`).
4. **Запрещены:** `any`, `as` без обоснования, `!`, `@ts-ignore`. Каждое подавление — сигнал «я не понял тип», а не «компилятор дурак».
5. `strict: true` не выключается.

---

## 🏷️ Соглашения именования

- `.tsx` — только файлы с JSX. Хуки, сторы, api, lib — `.ts`.
- **Компоненты:** `PascalCase.tsx`, имя файла = имя компонента.
- **Хуки:** `useThing.ts`. Прочие модули: `camelCase.ts`. Типы: `PascalCase`.
- **Стили:** `*.module.css` рядом с компонентом. Глобальные — `src/index.css`.
- **Тесты:** `__tests__/` рядом с тестируемым кодом внутри модуля.

## 🗺️ Куда положить новый код (Алгоритм)

1. **Знает про монеты/цены/портфель?**
    - ❌ Нет → `shared`: UI → `components/`, состояние/эффекты → `hooks/`, чистая функция → `lib/`, типы → `types/`.
    - ✅ Да → переходи к п. 2.
2. **Относится к существующему домену?**
    - ✅ Да → внутрь: сеть → `api/`, состояние запроса → `hooks/`, persisted-стейт → `store/`, JSX → `components/`, DTO → `types.ts`.
    - ❌ Нет → переходи к п. 3.
3. **Это новая пользовательская возможность (называется словом продукта)?**
    - ✅ Да → новый `features/<name>` со своей анатомией.
    - ❌ Нет, это просто экран на отдельном URL → `pages/<Name>Page` + роут.

## 🌱 Эволюция

- **Новый модуль** — при появлении возможности со своим состоянием или данными (пример будущего: `alerts` — уведомления о цене; будет зависеть от `market`).
- **В `shared`** — только по правилу второго использования.
- **Дробление модуля** — когда файлов ~15+ и внутри различимы под-домены.
- **Общий HTTP-клиент в `shared`** — только если появится второй API с тем же базовым URL. Пока клиент — приватная собственность `market`.
